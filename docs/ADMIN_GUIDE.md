# คู่มือเจ้าหน้าที่และผู้ดูแลระบบ — CDTI Smart Lost & Found

> หลักสำคัญ: ระบบ **ไม่ตัดสินแทนคน** คะแนนจับคู่และสัญญาณความเสี่ยงเป็นเพียงข้อมูลประกอบ การอนุมัติคืนของเป็นการตัดสินใจของเจ้าหน้าที่เสมอ และทุกการกระทำถูกบันทึกใน Audit log

## 1. บทบาท

| บทบาท | ทำอะไรได้ |
|---|---|
| ผู้ใช้ (user) | แจ้งของหาย/พบของ, ขอรับของ, ขอรหัสรับของ, ดูแจ้งเตือนของตัวเอง |
| เจ้าหน้าที่ (staff) | ตรวจคำขอรับของ, รับของเข้าคลัง, ส่งมอบของ, ตรวจสัญญาณ, เขียนบันทึกภายใน, ส่งเรื่องให้ admin, ดูสถิติและ Audit log |
| ผู้ดูแลระบบ (admin) | ทุกอย่างของ staff + แต่งตั้ง/ถอดถอนเจ้าหน้าที่, จำกัดสิทธิ์บัญชี, จัดการประเภท/สถานที่/จุดส่งมอบ, ปิดเรื่องที่ส่งต่อ, ลบบันทึกภายในของผู้อื่น |

- เจ้าหน้าที่ที่ยังไม่เปลี่ยนรหัสผ่านชั่วคราว หรือบัญชีถูกจำกัดสิทธิ์ จะ **ไม่มีสิทธิ์เจ้าหน้าที่** จนกว่าจะแก้ไข
- เจ้าหน้าที่ตรวจ/ส่งมอบของที่ตัวเองเป็นผู้พบหรือผู้ขอรับ **ไม่ได้** (กันผลประโยชน์ทับซ้อน) — ให้คนอื่นทำแทน

## 2. งานประจำวัน — หน้า `/admin` (รายการต้องตรวจสอบ)

เปิดทุกวันทำการ แล้วไล่ดูกล่องที่มีตัวเลข:

1. **ข้อพิพาท** — ของที่มีผู้ขอมากกว่า 1 คน (ข้อ 4)
2. **คำขอจากผู้ที่มีสัญญาณเสี่ยง** / **คำขอไม่ผ่านซ้ำหลายครั้ง** / **พฤติกรรมที่ต้องเฝ้าระวัง** — ตรวจละเอียดขึ้น (ข้อ 6)
3. **ของมูลค่าสูง** — ต้องผ่านขั้น "ยืนยันแล้ว" ก่อนอนุมัติ และต้องตรวจบัตรตอนส่งมอบ
4. **ความผิดปกติของการครอบครอง** — ของค้างกับผู้พบนาน, ส่งต่อแล้วแต่ยังไม่ยืนยันรับ, อนุมัติแล้วไม่มารับ, กรอกรหัสผิดหลายครั้ง
5. **เรื่องส่งต่อให้ admin**

## 3. ตรวจคำขอรับของ — `/admin/claims`

1. เปิดคำขอ จะเห็นคำตอบของผู้ขอเทียบกับ **จุดสังเกตลับ** ของผู้พบ (ผู้ขอไม่เห็นจุดสังเกตลับ)
2. ติ๊ก checklist (คำตอบตรงจุดสังเกต / ลักษณะ / เวลา-สถานที่ / Serial / หลักฐาน)
3. เลือกผล:

| ผล | ผู้ขอเห็นอะไร | ใช้เมื่อ |
|---|---|---|
| ต้องตรวจเพิ่ม | "อยู่ระหว่างตรวจสอบ" | ยังตัดสินไม่ได้ |
| น่าจะเป็นเจ้าของ | "อยู่ระหว่างตรวจสอบ" | คำตอบสอดคล้องเป็นส่วนใหญ่ |
| ยืนยันแล้ว | "อยู่ระหว่างตรวจสอบ" | ตรวจครบ — **จำเป็นก่อนอนุมัติของมูลค่าสูง** |
| อนุมัติ | "ผ่านการตรวจสอบ — รอนัดรับของ" | พร้อมให้มารับ |
| ข้อมูลไม่พอ | "ต้องการข้อมูลเพิ่มเติม" | ให้ส่งใหม่ได้หลัง 24 ชม. (สูงสุด 3 ครั้ง) |
| ปฏิเสธ | "ไม่สามารถยืนยันได้" | ปิดถาวร |

**ห้าม** บอกผู้ขอว่าตอบข้อไหนผิด หรือเล่ารายละเอียดของที่พบ ทั้งในระบบ ทางโทรศัพท์ หรือต่อหน้า — ข้อความแจ้งผลในระบบเป็นกลางโดยตั้งใจ ถ้าต้องจดเหตุผล ให้เขียนใน "บันทึกภายใน" (เห็นเฉพาะเจ้าหน้าที่)

## 4. ข้อพิพาท (มีผู้ขอหลายคน)

- เมื่อมีคนที่ 2 ขอรับของชิ้นเดียวกัน ทุกคำขอจะเป็น "มีข้อพิพาท" และ **อนุมัติไม่ได้** จนกว่าจะเหลือคำขอที่เปิดอยู่คำขอเดียว
- ตรวจเทียบทุกคำขอ → ปฏิเสธ / ข้อมูลไม่พอ กับคำขอที่ไม่ตรง → จากนั้นจึงอนุมัติคำขอที่ตรง
- เรื่องที่ตัดสินยาก (เช่น ทั้งสองฝ่ายตอบถูก) → กด **ส่งเรื่องให้ admin** พร้อมเหตุผล

## 5. การครอบครองและการส่งมอบ

### รับของเข้าคลัง — `/admin/custody`
- ของที่ "อยู่กับผู้พบ" / "ส่งต่อให้เจ้าหน้าที่" → เมื่อได้รับของจริง ให้บันทึก **เก็บในคลัง** พร้อมจุดที่เก็บ
- ของต้องอยู่ในความดูแลของเจ้าหน้าที่ก่อนจึงจะส่งมอบได้

### ส่งมอบ — `/admin/handovers`
1. ผู้ขอที่ได้รับอนุมัติกด **"ขอรหัสรับของ"** ในหน้าคำขอของตัวเอง ได้รหัส 6 หลัก ใช้ได้ 48 ชั่วโมง
2. ผู้ขอมาที่จุดส่งมอบ แจ้งรหัสกับเจ้าหน้าที่
3. เจ้าหน้าที่เปิดคำขอ → กรอกรหัส, เลือกจุดส่งมอบ
   - **ของมูลค่าสูง: ต้องตรวจบัตรจริงและเลือกประเภทบัตร**
   - ของทั่วไป: แนะนำให้ตรวจบัตรเช่นกัน
4. ผล "ส่งมอบเรียบร้อย" → ระบบปิดของเป็น "คืนแล้ว", ปิดประกาศของหายที่ผูกกันไว้, แจ้งผู้ขอและผู้พบ

| ข้อความ | ทำอย่างไร |
|---|---|
| รหัสไม่ถูกต้อง | ตรวจกับผู้รับอีกครั้ง — ผิดครบ 5 ครั้งรหัสจะล็อก |
| รหัสหมดอายุ / ถูกล็อก | ให้ผู้รับขอรหัสใหม่ (ขอได้สูงสุด 5 ครั้งต่อคำขอ) |
| ผู้รับยังไม่ได้ขอรหัส | ให้ผู้รับกด "ขอรหัสรับของ" ก่อน |

**ห้าม** ส่งของโดยไม่มีรหัส และเจ้าหน้าที่ไม่มีทางดูรหัสได้ (ระบบเก็บเป็นค่า hash) — รหัสมีเฉพาะผู้รับ

## 6. สัญญาณความเสี่ยง — `/admin/risk`

สัญญาณเกิดอัตโนมัติ (ขอรับถี่, ไม่ผ่านซ้ำ, ขอรายการเดิมซ้ำ, คำตอบเปลี่ยนไปจากเดิม, บัญชีใหม่ขอของมูลค่าสูง) — **ไม่ใช่ข้อกล่าวหา**

- เจ้าหน้าที่บันทึกผล: ต้องตรวจสอบ / พฤติกรรมที่ต้องเฝ้าระวัง / ตรวจแล้วไม่พบปัญหา
- **จำกัดสิทธิ์บัญชี** (admin เท่านั้น, ต้องมีเหตุผล): บัญชีนั้นจะแจ้งของและขอรับของไม่ได้ ผู้ใช้ได้รับข้อความแจ้งที่เป็นกลาง
- ห้ามใช้คำว่า "โกง/ขโมย" ในบันทึก ให้เขียนตามข้อเท็จจริง

## 7. บันทึกภายใน และการส่งเรื่องให้ admin

- บันทึกภายในเห็นเฉพาะเจ้าหน้าที่ แก้ไขไม่ได้ ลบได้เฉพาะผู้เขียนหรือ admin (การลบก็ถูกบันทึก)
- ส่งเรื่องให้ admin จากหน้ารายละเอียดคำขอรับของ → admin ปิดเรื่องที่ `/admin/escalations` พร้อมผลการพิจารณา

## 8. งานของ admin

| งาน | ที่ | หมายเหตุ |
|---|---|---|
| แต่งตั้ง/ถอดถอนเจ้าหน้าที่ | `/admin/users` | ให้ผู้นั้นสมัครบัญชีเองก่อน → ค้นหาด้วยอีเมล → เลือกสิทธิ์ → ใส่เหตุผล (เช่น เลขที่คำสั่ง) · เปลี่ยนสิทธิ์ตัวเองไม่ได้ · ถอด staff ทันทีเมื่อย้ายงาน/ลาออก |
| ประเภทสิ่งของ | `/admin/categories` | "มูลค่าสูง" = ต้องตรวจเข้มและตรวจบัตร · ลบไม่ได้ ให้ปิดใช้งานแทน |
| สถานที่ / จุดส่งมอบ | `/admin/locations`, `/admin/handover-locations` | ใช้เฉพาะสถานที่ที่สถาบันยืนยัน · ปิดใช้งานแทนการลบ |
| สถิติ | `/admin/stats` | ตัวเลขรวมเท่านั้น ไม่มีข้อมูลรายบุคคล |
| Audit log | `/admin/audit` | ใครทำอะไรเมื่อไร แก้/ลบไม่ได้แม้แต่ admin |

## 9. บัญชีและรหัสผ่าน

- ลืมรหัสผ่าน: หน้า login → "ลืมรหัสผ่าน?" → ลิงก์ทางอีเมล → ตั้งรหัสใหม่
- admin/เจ้าหน้าที่: ใช้รหัสผ่านยาวและไม่ซ้ำกับที่อื่น, ห้ามใช้บัญชีร่วมกัน, ห้ามให้คนอื่น login แทน
- สงสัยว่าบัญชีเจ้าหน้าที่ถูกใช้โดยคนอื่น: admin ถอดสิทธิ์ที่ `/admin/users` ทันที แล้วตรวจ `/admin/audit`

## 10. ทำอย่างไรเมื่อ…

| สถานการณ์ | ทำ |
|---|---|
| ผู้พบบอกว่ากรอกจุดสังเกตลับผิดหลังมีคนขอรับแล้ว | ผู้พบแก้เองไม่ได้ (กันการสมรู้ร่วมคิด) — ให้เจ้าหน้าที่ตรวจของจริงและเขียนบันทึกภายใน |
| ผู้ขอรับโทรมาถามว่าตอบข้อไหนผิด | ห้ามบอก — แจ้งว่าข้อมูลไม่เพียงพอ ให้ส่งข้อมูลเพิ่มตามระบบ |
| ของอนุมัติแล้วแต่ไม่มารับนาน | ดูกล่อง "ความผิดปกติของการครอบครอง" → ติดต่อผ่านช่องทางสถาบัน |
| ของค้างในคลังนานตามระเบียบสถาบัน | **[นโยบายสถาบัน]** ระบบยังไม่มีขั้นตอนจำหน่าย/บริจาค — ปฏิบัติตามระเบียบและบันทึกไว้ในบันทึกภายใน |
| ระบบใช้ไม่ได้ | เปิด `/api/health` — ถ้า `db: error` แจ้งผู้ดูแลเทคนิค (ดู `docs/HANDOVER.md` ข้อ "เหตุขัดข้อง") |
