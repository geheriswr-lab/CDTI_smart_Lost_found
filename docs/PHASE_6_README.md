## Flow

```
ประกาศพบของ → [ฉันคิดว่านี่อาจเป็นของฉัน] → ตอบแบบสอบถาม + แนบหลักฐาน (ลับ)
  → submit_claim()  ── แจ้งเตือนเจ้าหน้าที่ทุกคน
  → เจ้าหน้าที่เปิด /admin/claims/<id>: เห็นข้อมูลลับของผู้พบ ↔ คำตอบผู้ขอ + ตัวช่วย + checklist
  → review_claim(): needs_review / likely_owner / verified / approved / insufficient / rejected
  → ผู้ขอได้รับแจ้ง (เฉพาะ approved / insufficient / rejected — ข้อความกลาง ๆ)
```

## แบบสอบถามตามประเภท (`categories.claim_form`)

| แบบ | ใช้กับ | คำถามหลัก |
|---|---|---|
| general | ประเภทอื่น ๆ | ลักษณะ, จุดสังเกต, ของข้างใน, ที่/เวลาที่หาย |
| wallet | กระเป๋าสตางค์ | ลักษณะ, ของในกระเป๋า, ชื่อบนบัตร, จุดสังเกต, ที่/เวลา |
| key | กุญแจ | จำนวนดอก, พวงกุญแจ, ลักษณะดอก, จุดสังเกต, ที่/เวลา |
| electronics | โทรศัพท์, คอมพิวเตอร์, อิเล็กทรอนิกส์ | ยี่ห้อ/รุ่น, เคส, ภาพหน้าจอล็อก (อธิบาย), serial/IMEI, จุดสังเกต, ที่/เวลา |

- **ไม่มีคำถามไหนขอรหัสผ่าน/PIN/OTP/รหัสปลดล็อก** (มี test ตรวจทุกแบบฟอร์ม)
- ถ้าผู้ใช้พิมพ์สิ่งที่ดูเหมือนรหัส (เช่น "PIN 1234") หรือเลข 13 หลักขึ้นไป (เลขบัตร/บัญชี) ระบบปฏิเสธ ไม่บันทึก — ยกเว้นช่อง serial/IMEI
- admin เปลี่ยนแบบฟอร์มของหมวดได้ที่คอลัมน์ `categories.claim_form`

## ความปลอดภัย

- **ปิดช่องโหว่จาก Phase 1:** เดิม policy ให้ผู้ขอ insert/update claim ของตัวเองได้ทุกคอลัมน์ — ตั้ง `status='approved'` เองได้
  ตอนนี้ client เขียนตาราง `claims` ไม่ได้เลย ทุกอย่างผ่าน `submit_claim` / `cancel_claim` / `review_claim` (SECURITY DEFINER)
- **Anti-guessing**
  - ผู้ขอไม่เห็นข้อมูลลับของผู้พบเลย และไม่เห็น checklist/บันทึกของเจ้าหน้าที่ (`claim_reviews` เป็น staff-only)
  - สถานะระหว่างตรวจ (needs_review / likely_owner / verified) แสดงต่อผู้ขอเป็น "อยู่ระหว่างตรวจสอบ" เหมือนกันหมด และไม่ส่งแจ้งเตือน
  - ข้อความ insufficient / rejected เป็นกลาง ไม่บอกว่าข้อไหนผิด
  - ส่งซ้ำได้เฉพาะหลัง `insufficient`/`cancelled`, เว้น 24 ชม., **สูงสุด 3 ครั้งต่อรายการ** (`claim_attempt_count`) · `rejected` = จบ
  - ต่อคน: คำขอใหม่ไม่เกิน 3 รายการ/24 ชม. และค้างได้ไม่เกิน 5 รายการ
- **Verification level:** หมวด `is_high_value` → `enhanced` — ต้องผ่าน `verified` ก่อนจึง `approved` ได้ (ของทั่วไป: ต้องเป็น likely_owner หรือ verified ก่อน)
- **Conflict of interest:** เจ้าหน้าที่ที่เป็นผู้ขอหรือผู้พบของรายการนั้น ตรวจเองไม่ได้ (บังคับใน DB)
- **ผู้พบไม่เห็นคำขอ** ว่าใครขอหรือตอบอะไร · ผู้พบขอรับของที่ตัวเองแจ้งไม่ได้ · บัญชีถูกจำกัดสิทธิ์ขอไม่ได้
- **หลักฐาน:** bucket ลับ `<uid>/claims/<claim_id>/...`, ตรวจชนิดไฟล์จาก magic bytes (JPG/PNG/WebP/PDF ≤ 5 MB), สูงสุด 5 ไฟล์/คำขอ, trigger ตรวจว่าเป็นไฟล์ของผู้ขอเองสำหรับคำขอนั้นจริง
- เจ้าหน้าที่ดูหลักฐานผ่าน signed URL อายุ 60 วินาที
- `audit_logs`: `claim.submitted`, `claim.cancelled`, `claim.reviewed` (ไม่เก็บคำตอบ)
- **แก้ open redirect ที่หน้า login:** `?next=//evil.com` เคยพาผู้ใช้ออกไปเว็บอื่นหลังล็อกอินได้

## ตัวช่วยเจ้าหน้าที่ (ไม่ใช่การตัดสิน)

- Serial/IMEI ตรงกันไหม (ไม่สนตัวพิมพ์เล็กใหญ่/ขีด/ช่องว่าง)
- คำจากจุดสังเกตลับที่ปรากฏในคำตอบ · คำจากตำแหน่งที่พบที่ปรากฏในคำตอบ "ที่/เวลาที่หาย"
- ประวัติผู้ขอ: จำนวนคำขอทั้งหมด / ถูกปฏิเสธ / ข้อมูลไม่พอ · วันที่สมัคร
- เตือนเมื่อของชิ้นเดียวกันมีคำขอเปิดอยู่มากกว่า 1 รายการ (ระบบข้อพิพาทเต็มรูปแบบ = Phase 7)
