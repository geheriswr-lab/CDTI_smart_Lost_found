# CDTI Smart Lost & Found — โมเดลวิสาหกิจเพื่อสังคม (Social Enterprise)

> **หลักการ:** ผู้ที่ทำของหายต้องเข้าถึงบริการพื้นฐานได้ฟรีเสมอ รายได้ของระบบมาจากบริการเสริมและการสนับสนุน
> ไม่ใช้ความเดือดร้อนของเจ้าของของมาเป็นเงื่อนไข

ตัวเลขทุกตัวในเอกสารนี้เป็น **สมมติฐานสำหรับ Validation** ยังไม่ใช่ราคาจริง

---

## 1. สรุปสำหรับตอบอาจารย์

> โครงการใช้รูปแบบรายได้แบบผสม โดยประชาคมภายในสถาบันใช้บริการ Lost & Found ขั้นพื้นฐานได้โดยไม่เสียค่าใช้จ่าย
> รายได้มาจากสามทาง ได้แก่ ค่าดำเนินการจากสินน้ำใจที่เจ้าของให้ผู้พบโดยสมัครใจ ค่าบำรุงระบบจากสถาบัน/หน่วยงาน
> และความร่วมมือกับพันธมิตร รายได้ส่วนหนึ่งนำกลับมาพัฒนาและดูแลระบบ เพื่อให้โครงการดำเนินงานต่อได้อย่างยั่งยืน
> โดยไม่ลดทอนเป้าหมายทางสังคม

| บทบาท | ใคร |
|---|---|
| **Beneficiary** (ผู้ได้รับประโยชน์) | นักศึกษา บุคลากร และผู้มาติดต่อ ทั้งเจ้าของของและผู้พบ |
| **Customer** (ผู้จ่าย) | สถาบัน/หน่วยงาน พันธมิตร และเจ้าของที่ **สมัครใจ** ให้สินน้ำใจ |
| **Social Value** | เพิ่มโอกาสได้ทรัพย์สินคืน ลดการสวมรอยรับของ และส่งเสริมวัฒนธรรมการส่งคืน |
| **Revenue** | ค่าดำเนินการสินน้ำใจ ค่าบำรุงระบบ และค่าสนับสนุนจากพันธมิตร |

## 2. รายได้ 3 ทาง

| รายได้ | ใครจ่าย | ระบบได้อะไร | ในระบบตอนนี้ |
|---|---|---|---|
| **1. ค่าดำเนินการสินน้ำใจ** | เจ้าของที่สมัครใจให้สินน้ำใจ | 2% หลังคืนของสำเร็จ (ปรับได้) | ✅ ครบ flow ใน **โหมดสาธิต** (ไม่มีเงินจริง) |
| **2. ค่าบำรุงระบบ (Institutional Subscription)** | สถาบัน/หน่วยงาน | ค่าบำรุงรายเดือน/รายปี เช่น สมมติฐาน 12,000 บาท/ปี | ✅ บันทึกรายรับ + dashboard (สัญญาจริงทำนอกระบบ) |
| **3. ค่าสนับสนุนจากพันธมิตร (Partner Sponsorship)** | ร้านค้า/พันธมิตรที่สถาบันอนุมัติ | ค่าสนับสนุนรายเดือน/รายปี และมอบสิทธิประโยชน์ให้ผู้พบ | ✅ จัดการพันธมิตร คูปองอัตโนมัติ ใช้คูปอง และหน้า "ผู้สนับสนุน" |

**ฟรีเสมอ:** ค้นหา, แจ้งของหาย, แจ้งพบของ, ขอรับของ, การตรวจสอบ และการส่งมอบ

## 3. สินน้ำใจสำหรับผู้พบ — flow และกติกา

```
เจ้าของตั้งสินน้ำใจ (ไม่บังคับ) → มีผู้พบ → ตรวจสอบความเป็นเจ้าของ → ส่งมอบ
→ ยืนยัน Returned → เจ้าของยืนยันการมอบ → ผู้พบเลือก "รับ" หรือ "มอบให้โครงการ"
→ เจ้าหน้าที่บันทึกการโอน → ระบบได้ค่าดำเนินการ
```

ตัวอย่าง: สินน้ำใจ 500 บาท → ผู้พบได้ 490 บาท → ระบบได้ 10 บาท (2%)

| กติกา | บังคับใช้ที่ |
|---|---|
| ใช้คำว่า "สินน้ำใจสำหรับผู้พบ" ไม่ใช่ "ค่าตอบแทนการคืนของ" | ข้อความในระบบ + unit test ห้ามคำที่สื่อว่าเป็นเงื่อนไข |
| ตั้งได้เฉพาะเจ้าของ ผู้พบไม่มีช่องทางเรียกเงิน | `pledge_reward` / `offer_reward_after_return` |
| สินน้ำใจเกิดหลังส่งมอบสำเร็จเท่านั้น ไม่ใช่เมื่อมีคนกดว่า "พบของ" | trigger บน `handovers` |
| ไม่มีผลต่อการตรวจสอบหรือการส่งมอบ | `review_claim` / `complete_handover` ไม่อ่านตาราง rewards (มีทดสอบ: ส่งมอบสำเร็จแม้ยังไม่จ่าย) |
| ไม่แสดงจำนวนในประกาศสาธารณะ ผู้พบรู้หลังคืนสำเร็จเท่านั้น | public views ไม่มีคอลัมน์ reward + `my_rewards()` |
| ไม่เปิดเผยตัวตนระหว่างเจ้าของกับผู้พบ | `my_rewards()` ไม่คืน id/ชื่อของอีกฝ่าย |
| เจ้าของเปลี่ยนหรือยกเลิกได้ก่อนได้ของคืน และให้ย้อนหลังได้ภายใน 30 วัน | settings `reward_offer_days` |
| จำนวนเต็ม 20–5,000 บาท (ปรับได้) | `assert_reward_amount` |
| ค่าดำเนินการ = max(จำนวน × %, ขั้นต่ำ) และไม่เกินจำนวน | `reward_fee` |
| ผู้พบเลือกมอบให้โครงการได้ | `set_reward_choice` |
| ทุกขั้นบันทึก Audit log | `reward.*` |

**ทำไมยังเป็นโหมดสาธิต:** การรับเงิน, escrow และการโอนจริงเกี่ยวข้องกับบัญชี ภาษี เงื่อนไขของผู้ให้บริการชำระเงิน และระเบียบสถาบัน
ต้องให้ฝ่ายที่เกี่ยวข้องอนุมัติก่อน โค้ดแยกจุดชำระเงินไว้ที่ `pay_reward_demo` / `settle_reward` เพื่อให้เปลี่ยนเป็นผู้ให้บริการจริงได้ภายหลัง

## 4. Business Model Canvas

| ช่อง | เนื้อหา |
|---|---|
| **Customer Segments** | ผู้ได้รับประโยชน์: นักศึกษาอาชีวะ/อุดมศึกษา บุคลากร ผู้มาติดต่อ · ผู้จ่าย: สถาบัน/หน่วยงานภายใน, ร้านค้าและพันธมิตร, เจ้าของที่สมัครใจให้สินน้ำใจ · อนาคต: โรงเรียน มหาวิทยาลัย หอพัก องค์กร |
| **Value Propositions** | เจ้าของ: โอกาสได้ของคืนสูงขึ้น ใช้ฟรี ปลอดภัยจากการสวมรอย · ผู้พบ: คืนของง่าย ไม่ต้องติดต่อกันเอง ได้รับการขอบคุณ/สิทธิประโยชน์ · สถาบัน: ระบบหลังบ้าน จุดรับของกลาง ประวัติการครอบครอง Audit log สถิติ และพื้นที่ที่ของหายบ่อย · พันธมิตร: ภาพลักษณ์ CSR และความสัมพันธ์กับชุมชนในสถาบัน |
| **Channels** | เว็บแอป (มือถือ), QR ที่จุดรับของ/บอร์ดประชาสัมพันธ์, ปฐมนิเทศ, งานกิจการนักศึกษา, ร้านพันธมิตร |
| **Customer Relationships** | Self-service + เจ้าหน้าที่ตรวจสอบ, แจ้งเตือนอัตโนมัติ, หน้า "ผลลัพธ์ทางสังคม" ที่โปร่งใส |
| **Revenue Streams** | 1) ค่าดำเนินการสินน้ำใจ 2) ค่าบำรุงระบบจากสถาบัน 3) ค่าสนับสนุนจากพันธมิตร (+ ผู้พบมอบสินน้ำใจให้โครงการ, เงินบริจาค) |
| **Key Resources** | แพลตฟอร์ม (Next.js + Supabase), เจ้าหน้าที่ที่จุดรับของ, จุดส่งมอบ, เครือข่ายพันธมิตร, ข้อมูลสถิติแบบรวม |
| **Key Activities** | ตรวจสอบความเป็นเจ้าของ, ดูแลการครอบครองของ, ส่งมอบอย่างปลอดภัย, ดูแลระบบ, หาและดูแลพันธมิตร, รายงานผลลัพธ์ |
| **Key Partners** | หน่วยงานในสถาบัน (กิจการนักศึกษา, IT, การเงิน), ร้านค้าในสถาบัน, ผู้ให้บริการ cloud (Supabase/Vercel), ผู้ให้บริการชำระเงินในอนาคต |
| **Cost Structure** | ค่า hosting/ฐานข้อมูล/โดเมน/อีเมล (ตามแผนผู้ให้บริการ), เวลาดูแลระบบ, สื่อประชาสัมพันธ์/QR, ค่าธรรมเนียมชำระเงิน (เมื่อใช้เงินจริง) · สิทธิประโยชน์ผู้พบเป็นต้นทุนของพันธมิตร ไม่ใช่ของโครงการ |

**ตัวชี้วัดผลลัพธ์ทางสังคม** (มีในระบบแล้ว: `/impact`, `/admin/stats`, `/admin/se`): จำนวนของที่คืนสำเร็จ, อัตราการคืน, เวลาเฉลี่ยจนคืน, จำนวนสินน้ำใจ, เงินที่ถึงมือผู้พบ, เงินที่ผู้พบมอบให้โครงการ, สิทธิประโยชน์ที่มอบ

## 5. ต้อง Validate: 2% พอหรือไม่

| สินน้ำใจ | ค่าดำเนินการ 2% |
|---|---|
| 100 บาท | 2 บาท |
| 300 บาท | 6 บาท |
| 500 บาท | 10 บาท |

2 บาทจากสินน้ำใจ 100 บาทอาจไม่พอค่าธรรมเนียมต่อรายการของผู้ให้บริการชำระเงิน (ต้องสอบถามอัตราจริง) ระบบจึงให้ admin ปรับได้โดยไม่ต้องแก้โค้ด เพื่อทดลองทางเลือกต่อไปนี้:

- **% + ขั้นต่ำ** เช่น 2% ขั้นต่ำ 5 บาท (ตั้ง "ค่าดำเนินการขั้นต่ำ" ที่ `/admin/se`)
- **เปอร์เซ็นต์อื่น** เช่น 3–5%
- **ไม่หักจากผู้พบ แต่ให้เจ้าของสมทบค่าระบบเอง** (ยังไม่มีในระบบ — ทางเลือกสำหรับรอบถัดไป)
- **พึ่งค่าบำรุงระบบเป็นหลัก** ให้ค่าดำเนินการเป็นรายได้เสริม

**จุดคุ้มทุนคร่าว ๆ:** ต้นทุนต่อปี ≤ ค่าบำรุงระบบ + ค่าสนับสนุนพันธมิตร + (จำนวนสินน้ำใจต่อปี × ค่าดำเนินการเฉลี่ย) + เงินที่ผู้พบมอบให้โครงการ

**คำถามสำหรับ Validation:**

| กลุ่ม | คำถาม |
|---|---|
| เจ้าของของ | ถ้าได้ของคืน จะให้สินน้ำใจไหม เท่าไร และรับได้ไหมถ้าระบบหัก 2% |
| ผู้พบ | สินน้ำใจหรือคูปองทำให้อยากส่งคืนมากขึ้นไหม และจะเลือกมอบให้โครงการไหม |
| สถาบัน/หน่วยงาน | มีงบดูแลระบบลักษณะนี้ไหม คุณค่าที่อยากได้คืออะไร (สถิติ ลดงานเคาน์เตอร์ Audit) |
| ร้านค้า | ยินดีให้คูปองหรือค่าสนับสนุนเท่าไร และคาดหวังอะไรกลับ |

**ตัววัด:** % ของที่คืนแล้วมีสินน้ำใจ, สินน้ำใจเฉลี่ย, % ที่ผู้พบมอบให้โครงการ, อัตราการใช้คูปอง, จำนวนหน่วยงาน/ร้านที่ตกลงสนับสนุน

## 6. สิ่งที่ต้องขออนุมัติก่อนใช้เงินจริง

- ฝ่ายการเงิน/กฎหมายของสถาบัน: รูปแบบสินน้ำใจ ค่าธรรมเนียม การรับชำระ และภาษี
- เลือกผู้ให้บริการชำระเงิน และกำหนดว่าใครเป็นผู้รับเงินและผู้โอนให้ผู้พบ
- เงื่อนไขการใช้งานและนโยบายความเป็นส่วนตัวที่ระบุเรื่องสินน้ำใจและพันธมิตร
- สัญญา/ข้อตกลงกับพันธมิตร (ห้ามเงื่อนไขที่ทำให้การคืนของขึ้นกับสปอนเซอร์ และห้ามขอข้อมูลผู้ใช้)
